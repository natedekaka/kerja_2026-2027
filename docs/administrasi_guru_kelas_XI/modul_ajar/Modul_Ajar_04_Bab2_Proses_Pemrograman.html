04. Proses Pemrograman — Analisis sampai Pengujian

A. TUJUAN PEMBELAJARAN

Peserta didik mampu menganalisis proses pemrograman: analisis masalah → perancangan → implementasi → pengujian & debugging.

B. PEMAHAMAN BERMAKNA

Peserta didik mampu menganalisis proses pemrograman: analisis masalah → perancangan → implementasi → pengujian & debugging.

C. PERTANYAAN PEMANTIK

  1. Mengapa seorang programmer perlu melakukan analisis sebelum menulis kode?
  2. Apa yang terjadi jika sebuah aplikasi langsung di-coding tanpa perancangan terlebih dahulu?
  3. Pernahkah kamu mengalami error saat coding? Bagaimana cara kamu mengatasinya?

D. KEGIATAN PEMBELAJARAN

Tahap Aktivitas Waktu
Pendahuluan 1) Orientasi, apersepsi, motivasi 15’
2) Pertanyaan pemantik 10’
Inti 1) Studi Kasus: Analisis masalah “Membuat program kasir sederhana” — identifikasi input (daftar belanja, harga), proses (perhitungan total, diskon, pajak), output (struk belanja) (45’)
2) Perancangan: Menulis pseudocode dan flowchart untuk solusi, termasuk penanganan error (input non-numerik, stok habis) (45’)
3) Implementasi: Coding program kasir sederhana dalam Python — fungsi hitung_total, cetak_struk, validasi_input (45’)
4) Pengujian: Testing dengan berbagai input: normal (belanja 3 item), batas (0 item), error (huruf di harga) — debugging dan perbaikan kode (35’) 170’
Penutup Refleksi, kesimpulan, tugas 30’
